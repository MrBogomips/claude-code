# Client-Facing Style Guide

The deliverable must read as if it had been written for the customer from the start — not derived
from an internal assessment, an estimation exercise, or an AI-assisted workflow.

## Target audience

Assume a technically competent audience that is **not** familiar with internal terminology, project
history, or organization-specific practices:

- Solution Architects and Enterprise Architects
- Technical Leads
- Engineering Managers and IT Managers
- Project Sponsors
- Technical Customer Representatives

Write for the most senior technical reader: precise, substantiated, and respectful of their time.

## Voice

The writing must be:

- **Professional** — measured and credible
- **Technical** — accurate and specific
- **Clear and precise** — unambiguous, well-defined terms
- **Consultative** — explains rationale, frames decisions, guides the reader
- **Enterprise-oriented** — appropriate for a formal customer deliverable
- **Well-structured** — logical order, easy to navigate

## Prefer

- Complete sentences and developed paragraphs
- Contextual explanation and clear rationale where it helps the reader
- Logical transitions between sections
- Well-developed technical descriptions

## Avoid

- Excessive brevity and bullet-point-only explanations where prose is warranted
- AI-style summarization (terse, listy, context-free)
- Marketing language and superlatives
- Unnecessary verbosity — enough detail to be useful, no more
- Any meta-reference to the conversion, AI, internal revisions, or removed content

> Bullet lists remain appropriate for genuinely enumerable content (requirements, dependencies,
> steps). The rule is against using bullets as a substitute for explanation, not against lists.

## Acronyms and terminology

- Expand acronyms on first use unless universally recognized (e.g., API, HTTP, SQL may stand).
- Eliminate organization-specific abbreviations entirely.
- Replace internal jargon with clear, standard technical language.
- Standardize terminology across the document; if a **~~knowledge base** glossary is connected, align
  to it.
- Prioritize clarity over brevity.

## Structure

- Open with a short context/purpose framing before detail.
- Group related material; order sections so each builds on the last.
- Use descriptive headings that state the section's subject, not internal labels.
- Ensure cross-references and terminology are consistent throughout.
