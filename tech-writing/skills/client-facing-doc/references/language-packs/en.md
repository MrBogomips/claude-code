# Language Pack: English (en)

Use these conventions when the deliverable is produced in English. The skill preserves the source
document's own section structure, so this pack provides common labels and phrasing conventions rather
than a fixed template.

## Common section labels

| Concept | Preferred English label |
|---------|-------------------------|
| Overview / context | Overview |
| Scope | Scope |
| Architecture | Solution Architecture |
| Non-functional requirements | Non-Functional Requirements |
| Constraints | Constraints |
| Dependencies | Dependencies |
| Integrations | Integration |
| Risks | Risks |
| Deployment | Deployment |
| Operations | Operations |
| Assumptions | Assumptions |
| Glossary | Glossary |

## Conventions

- Date format: `YYYY-MM-DD` or `D Month YYYY`.
- Use the serial structure of full sentences; prefer "the solution provides…" over telegraphic notes.
- Universally recognized acronyms that may stand unexpanded: API, HTTP(S), REST, SQL, JSON, XML, URL,
  CPU, RAM, SLA, UI, UX. Expand all others on first use.
- Avoid first-person plural that implies the delivery organization ("we will") where a neutral
  construction reads better ("the solution will", "the implementation provides").

## Boilerplate phrasings

- Section opener: "This section describes…"
- Rationale connector: "This approach was chosen because…"
- Dependency framing: "The solution depends on…"
- Risk framing: "There is a risk that…, mitigated by…"
