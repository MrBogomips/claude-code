# kaizen/asset-attribution Specification

## Purpose
Turns the incidents of one session into findings tied to the asset responsible, and decides for each
finding whether kaizen may propose an edit, may only advise, or should point at the tool that owns it.

## Requirements

### Requirement: The retrospective runs only at the user's request
The kaizen skill SHALL run only when the user asks for it, by invoking it or by accepting the hook's
offer. The model SHALL NOT start it on its own.

#### Scenario: Offer not accepted
- **WHEN** the hook's offer is shown and the user goes on with other work
- **THEN** the kaizen skill is not invoked

### Requirement: Every finding cites an incident of this session
Each finding SHALL cite a concrete incident of the current session (a tool error, a rework, a user
correction, an ambiguity, a skill that misfired or failed to fire, a poor agent result, contradictory
instructions met) and the asset text it links to. A run with no such incident SHALL report that in one
line and change nothing.

#### Scenario: Clean session
- **WHEN** kaizen runs on a session with no incident linked to an asset
- **THEN** it replies in one line that there is nothing to review and writes nothing

#### Scenario: No generic advice
- **WHEN** an asset could be worded better but caused no incident in the session
- **THEN** kaizen reports no finding for it

### Requirement: Each active asset is classified by origin
The skill SHALL classify each asset it links to an incident as project (tracked by git inside the
repository and not generated), local (untracked inside the repository), generated, user, plugin, auto
memory, managed or bundled. Only project assets SHALL be editable. Outside a git repository every asset
SHALL be treated as not editable.

#### Scenario: Plugin skill misfired
- **WHEN** a skill provided by an installed plugin fired on an unrelated request
- **THEN** the finding is advice routed to that plugin's repository, with no edit proposed

#### Scenario: Generated project file
- **WHEN** the responsible asset is a project skill generated by a framework
- **THEN** the finding is advice to change it through the framework that generates it

### Requirement: Findings owned elsewhere become a single pointer
When a finding is the job of a harness feature or another available tool (static audit of instruction
files, unused skills, permission allowlists, cross-session reports, saving corrections, skill authoring),
the skill SHALL emit one pointer line naming that feature instead of a proposal, and only if the feature
is available in the session.

#### Scenario: Static contradiction not met in the session
- **WHEN** two rule files contradict each other but the session never acted on either
- **THEN** kaizen reports at most a pointer to the instruction-file audit and proposes no edit

### Requirement: External assets receive advice with an owner route
For an asset that is not a project asset, the skill SHALL give advice naming the asset, its origin, the
incident, the suggested change and who can make it, and SHALL NOT edit it.

#### Scenario: User-level rule caused rework
- **WHEN** a rule in the user's global configuration caused a rework
- **THEN** kaizen lists advice for the user to change that file and edits nothing

### Requirement: Auto memory is promoted, never edited
The skill SHALL NOT edit auto memory. When a memory fact shaped the session and belongs to the project,
the skill MAY propose adding it to a project asset.

#### Scenario: Memory fact mattered
- **WHEN** a machine-local memory fact prevented an error in the session
- **THEN** kaizen may propose adding it to a project file and leaves the memory file unchanged
