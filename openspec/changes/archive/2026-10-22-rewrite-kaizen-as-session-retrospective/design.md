# Design

## Context

See proposal.md for the motivation. Constraints that shape the approach:

- Claude Code has no hook that runs before a session closes and lets the model act. `SessionEnd` cannot
  block, discards its JSON output, gets a 1.5 s budget that plugin hook timeouts do not raise, and takes
  no prompt or agent hooks. `Stop` fires at the end of every turn (not on a user interrupt), and its
  `additionalContext` makes the conversation continue once so the model can act on it
  (code.claude.com/docs/en/hooks).
- The harness already covers static audits and cleanup: `/doctor prompt-audit` (instruction files that
  are stale, written for older models, or contradict each other), `/doctor` (unused skills, MCP and
  plugins, slow hooks), `/skill-doctor`, `/usage`, `/insights` (cross-session friction), and
  `/fewer-permission-prompts`; auto memory saves corrections by itself.
- Repository rules: generic use (no dependence on the author's configuration or on other plugins being
  installed), macOS/BSD shell compatibility, markdown and JSON only, no build step.

## Goals / Non-Goals

**Goals:**
- One skill, one read-only agent, one hook script: about 365 lines in total.
- The model is involved only when the session shows friction, and at most once per session.
- Findings exist only for incidents of this session, tied to the asset responsible.

**Non-Goals:**
- Static audits, cross-session analytics, cost attribution, permission allowlists, skill authoring.
- Persisted history of retrospectives, or any edit to assets the project does not own.

## Decisions

**D1. Editable means tracked and not generated.** A project asset is a file tracked by git inside the
repository and not generated by a tool or framework. Untracked local files, generated files, user,
plugin, managed and bundled assets, auto memory, and everything outside a git repository get advice
only. Every edit is therefore undoable with git, so kaizen needs no backup, no state and no commit.
Alternative rejected: context-hygiene's backup item and irreversible-item rules, which suit deletions of
untracked memory but add machinery here.

**D2. kaizen never creates skills or agents.** An incident that calls for a new one becomes advice with
the brief, pointing at an authoring skill only if one is available. Authoring and evals belong to tools
built for them, and this rule removes the main source of uncontrolled growth.

**D3. Auto memory is promoted, never edited.** Auto memory is machine-local and outside the repository.
kaizen may propose moving a fact that mattered into a project file; any leftover duplicate in memory is
for a pruning tool to find.

**D4. The review covers any model-facing text.** The reviewer checks proposed after-text for skills,
agents, rules, CLAUDE.md, commands and output styles, not only skills, agents and rules: CLAUDE.md is the
most frequent target and the likeliest source of contradictions. The reviewer never audits existing text
(that is `/doctor prompt-audit`). Its checklist lives once, in the skill's `references/proposals.md`, and
is passed in the dispatch prompt, so a skill installed without the plugin can run the same review through
a general-purpose subagent. The agent file only restricts tools to `Read, Grep, Glob`.

**D5. The skill runs only at the user's request.** The gate lives in the hook plus the model's judgment
of the hook context; the skill itself does not re-check it and never starts on its own.

**D6. Chat only.** Recap, authorization and report happen in chat; authorization is by item ID with an
option letter. The only file kaizen writes outside authorized edits is the hook's per-session marker in
`${CLAUDE_PLUGIN_DATA}`.

**D7. Stop hook with `additionalContext`, not `systemMessage`, SessionEnd or a prompt hook.** The model
has to judge reworks and ambiguities, which a script cannot see, so the offer goes to the model.
Rejected: `systemMessage` to the user only (no model judgment); SessionEnd (cannot reach the model); a
prompt or agent hook on Stop (a model call on every turn). The continuation costs one short turn, once per
session, and only when a mechanical signal tripped.

**D8. Stdin and transcript are parsed with grep, without jq or python.** Neither is guaranteed on the
user's machine, and macOS can prompt to install developer tools when `python3` is first called. Inside a
JSON string every quote is escaped, so an unescaped `"key":` match is a real key; the first match is the
top-level one because Claude Code writes top-level keys first. The transcript format is internal: a
pattern miss means no offer, never a wrong action.

**D9. Unattended runs are detected best-effort.** Neither `CLAUDE_CODE_SESSION_ATTENDED` nor
`CLAUDE_CODE_ENTRYPOINT` is documented; the hook skips when the first is `0` or the second starts with
`sdk`, and documents `KAIZEN_STOP_HOOK=0` as the supported opt-out.

### Spike results (Claude Code 2.1.306, throwaway plugin in a temp directory)

- Stop stdin is compact JSON: `session_id`, `transcript_path`, `cwd`, `prompt_id`, `permission_mode`,
  `effort`, `hook_event_name`, `stop_hook_active`, `last_assistant_message`, `background_tasks`,
  `session_crons`.
- `{"hookSpecificOutput":{"hookEventName":"Stop","additionalContext":"…"}}` made the model continue once;
  the next Stop had `stop_hook_active: true`. In `claude -p` the continuation replaced the run's final
  result, hence D9.
- The hook environment had `CLAUDE_PLUGIN_ROOT`, `CLAUDE_PLUGIN_DATA`, `CLAUDE_PROJECT_DIR`;
  `CLAUDE_CODE_ENTRYPOINT=sdk-cli` and `CLAUDE_CODE_SESSION_ATTENDED=0` under `claude -p` (`cli` and `1`
  in an interactive session).
- `${CLAUDE_SESSION_ID}` is substituted in a plugin SKILL.md.
- A failed Bash call is recorded as `"is_error":true`; user interruptions as
  `[Request interrupted by user]` or `[Request interrupted by user for tool use]`.
- A directory-form plugin agent `agents/<dir>/AGENT.md` is addressed as `<plugin>:<dir>:<name>`, so the
  reviewer is `kaizen:kaizen-reviewer:kaizen-reviewer`.
- `claude plugin validate --strict` accepts the `hooks.json` shape used.

## Risks / Trade-offs

- [No pre-close hook] The offer comes at the first end of turn where the gate trips, possibly mid-task →
  it is worded "before the session closes" and the model offers it only if the full gate trips.
- [Undocumented attended signal] A future version may drop the variables → the opt-out stays documented;
  the worst case is one extra short turn in a headless run.
- [Transcript format drifts] Patterns may stop matching → fail-silent; the hook test pins the patterns,
  to be re-checked after Claude Code upgrades.
- [False offers] TDD runs produce tool errors on purpose → the offer appears at most once and the model
  still judges the gate before mentioning it.
- [Install without the plugin] `npx skills add` installs the skill alone: no hook and no agent → on-demand
  use only, with the general-purpose reviewer fallback; the README says so.

## Migration Plan

Users of 1.2.0 lose the KPI engine; `.kaizen/runs/` folders are left untouched and no longer read. The
1.2.0 tree stays in the repository history. Rollback is reinstalling 1.2.0 from history.
